# PhD 申请管理与审核

作为这组三个 skill 的入口，协调资料准备和网页执行。用中文与用户沟通，按目标申请表要求保留英文姓名、项目名称和最终答案。专业、入学年份和学校项目名单均是运行时输入，不预置默认学校、专业或年份。

## 开始或恢复

1. 先读 [工作区契约](references/workspace-contract.md) 和 [审核协议](references/approval-protocol.md)。它们是三个 skill 共用的数据和审核规则。
2. 找到用户明确指定的申请资料目录；有既存 case 则读取继续，只补问缺失或冲突信息。没有时，在当前工作区建立独立的 `phd-applications/<case-id>/`，按 [模板目录](assets/) 创建运行记录。不得把个人资料写回已安装的 skill。
3. 首次收集：专业及研究方向、目标入学季和年份、用户已有学校与具体项目名单（最好附官网/申请入口）、已有资料及账号情况。若只给学校名，先补齐具体项目，不能自行选定专业。名单可以以后追加，但不得自行扩展。
4. 明确本次操作对象和停止范围。首次测试为 `draft_only`：从用户给定名单中，依据其资料、资格、研究兴趣及开放状态提出一个候选，简述理由；让用户选定或沿用其明确授权的选择后执行。不得为测试去创建虚假身份或申请。
5. 用户尚未给资料时可以完成说明、空白模板和离线检查；不要启动真实注册。资料或门户缺失时，仅暂停依赖它的步骤，继续独立可完成的整理。

## 路由到两个工作 skill

| 需求 | 加载并执行 | 交接结果 |
| --- | --- | --- |
| 收集、提取、核实、更新个人信息或整理补充题候选文本 | [phd-applicant-profile](../phd-applicant-profile/SKILL.md) | 已确认事实、待核实项、资料来源、项目专属答案 |
| 检查给定项目的当前要求、注册/登录、填表、审核后上传、保存核验 | [phd-application-executor](../phd-application-executor/SKILL.md) | 页面实际状态、待审核动作、已保存证据、剩余事项 |

读目标 skill 后再开展对应工作。缺少任一依赖文件时，指出缺失并修复安装，不凭记忆绕过其规则。默认同一会话顺序完成；只有独立的材料整理可并行，不能让多个执行者同时操作同一门户或改写同一申请记录。

不额外建立“项目调研 skill”。核实用户给定项目的官方要求、申请开放状态和字段，属于执行前准备；不演变成全美搜校或擅自扩大名单。可先从现有材料建通用资料，再按实际门户补齐必要字段，无需先登录所有项目。

## 管理审核

- **任何文件上传、推荐人邀请（含重发/提醒）、付款、最终提交，必须先取得用户对具体动作的明确确认。** 不能以“帮我申请”“继续”“试一遍”或批准另一个动作代替。上传包括向云端/中转服务传送文件。
- **所有补充问题均人工审核。** 展示原题、上下文、长度/选项限制，先让用户说明如何回答；根据其指示准备完整答案/精确选项，经审核后才允许录入。用户直接给出最终答案并明确要求填入时，可以同时满足这两步。
- 审核时先完成可审查的准备工作；使用审核协议的具体展示项和有效期规则，不让用户批准一个尚未确定内容的操作。可以一次批准逐项列明的文件或答案。
- 审核是用户的决定。manager 可以检查证据是否完整、是否已获准，不能替用户批准，也不能把另一个 agent 的“检查通过”当作用户同意。
- 普通已授权的基本信息录入、页面读取和草稿保存继续执行，无需逐字段重复确认。补充题、个人选择或声明不能偷偷归为“基本信息”绕过审核。
- `draft_only` 下不付款、不最终提交、不作等价的签署/提交动作。上传和邀请也不因处于草稿阶段自动获准。用户明确修改范围后才更新 `case.json`；修改范围本身不代替具体付款或提交确认。
- 尊重当前运行环境的权限和确认要求。skill 提供工作指令，不构成工具权限隔离，也不保证所有网站均可自动化。

## 持续核对与结束

按依赖关系处理待办；遇到等待审核的栏位可以继续其他互不影响且已授权的内容。页面强制要求未获批文件或答案时，停在该处并说明阻塞，不能造占位答案跨过去。

复用批准前核对内容、项目、年份、目标栏位和当前页面是否一致。恢复运行先检查已保存字段、上传状态和邀请状态，不从头重放动作。资料更新后标记受影响的已填字段和审核项供重新核对，不能悄悄覆盖已确认的个人事实。

每次汇报应区分：已保存并核验、已输入但保存未证实、待用户补充、待人工审核、待人工接管。阶段完成时提供申请入口和简短剩余清单，不把可保存草稿说成完整申请，不把已选文件说成上传成功。

首次真实测试成功的依据是：项目及入学季正确；可执行字段与已确认资料一致；补充答案和上传遵守审核；有网站保存成功及重新读取的证据；未付款或最终提交。到达草稿终点就汇报结果，不主动要求升级到付款或提交。若只能完成部分草稿，明确记录完成范围与阻塞，保留恢复位置。
