# 门户操作与恢复

在读取共享工作区契约和审核协议后使用本流程。只记录契约允许的状态和字段；下文的描述不是一套替代 schema。

## 进入正确申请

- 从用户名单中的项目官网核对当前入学年度的官方申请入口。学校官网、系所说明和实际门户之间有差异时，保留来源和原文差异，先解决影响目标或填写的冲突。
- 核对门户显示的学校、学位、项目/track、入学学期和年度。相同学校的不同门户、硕士与博士、当前年度与上一年度不可混用。
- 查看账号与申请记录，优先恢复已有申请。若账号状态不清楚，先查门户/用户已提供的信息；不要为了测试建立第二个账号，也不要自动发起密码重置邮件。
- 创建账号属于本次执行范围时，可使用已确认姓名和申请邮箱完成普通注册。遇到账号声明、站点条款或验证码，按其实际内容及运行环境规则处理，不替用户作未经确认的事实声明。
- 不读取其他学校或与本次任务无关的邮件。若需要查找激活邮件，先确认当前工具和任务授权允许，限于目标学校的对应注册邮件；需要人工验证的环节交给用户。记录邮箱地址或账号引用即可，不记录密码、验证码或激活令牌。

## 判断字段来源

先判断字段属于哪一类，再操作；“能从 CV 推测”不等于“已确认”。

| 类别 | 处理 |
| --- | --- |
| 通用事实字段 | 与已确认 profile 值对应，核对标签和单位后填入。 |
| 缺失或有冲突的事实 | 原题、现有候选值和差异交回澄清，先处理其他独立字段。 |
| 项目补充问题 | 保留完整原题、所有相关选项、必填性、字数/字符限制及填写位置；按方向与最终答案两阶段审核。 |
| 文件栏目 | 先识别所需材料、格式、大小、页数、命名或翻译要求；准备准确版本，按文件审核流程操作。 |
| 推荐人或消息相关字段 | 先查明录入/保存是否发通知，任何可能触发通知的动作之前审核。 |
| 声明、权利选择与承诺 | 展示实际文字，让用户决定；不从其他学校的选择推断。 |

仅重新输入基本资料的字段可以按已确认事实填写；真正的项目补充问题不能因形式简单而降格为普通事实字段。即使题目只有导师下拉菜单、研究领域多选或一个短答框，仍要由用户给方向并批准精确最终选择。模糊边界按补充问题处理。项目页面的动态追问出现后，作为新问题处理；父问题批准不覆盖子问题。

未获填写批准时，不把草拟答案暂填到门户“让用户看看”，因为门户可能自动保存。可以在本地或对话里整理待审答案。若用户提供的原文超长，先展示具体限制及调整后的完整版本，获批准后录入，不自行截断。

## 文件审核与上传

1. 从当前栏目读取要求；核对实际文件内容与学校/项目，尤其注意 SOP、personal statement、writing sample 的不同版本。
2. 按共享审核协议固定文件版本并展示可检查的文件和目标；告知上传目的地是学校还是中转服务。若预览工具会先上传文件到外部服务，应先为该传输取得批准，不能用“为了审核”绕过上传审核。
3. 等待准确授权。不要提前打开文件选择器、拖拽文件、填写自动上传控件或调用上传工具。只要用户尚未审核，文件就留在已授权的本地范围内。
4. 执行前重新核对文件版本、目标项目和栏目，确认与审核对象完全一致；变化即使文件名未变也需新审核。
5. 上传后核对门户附件名称、类型、状态以及可取得的预览，确认文件进入正确栏目。仅看到进度条或点击完成不能证明学校已保存。
6. 若结果未知，先查看附件列表、刷新/重新进入或其他只读方式确认；不要立即重新上传。替换或重传也要明确具体版本与目标是否仍受批准覆盖，并遵守共享协议。

同一份文件用于另一学校、另一项目或另一栏目属于新的审核对象。若用户希望一次审核多个上传目标，应在审核前逐项列清文件版本和全部目标，由用户明确批准这份具体清单。

## 推荐人及其他外部动作

有些门户会在录入或保存推荐人信息时发出请求，而非等到最终提交。先读页面说明，必要时只读查看帮助。无法确认是否自动发信时，按可能发信处理，取得对此具体邀请的批准后才录入/保存。

邀请审核同时展示推荐人姓名、邮箱、学校/项目，以及会被锁定的相关选择，例如放弃查看推荐信权利。让用户自己决定这类选择。首次邀请的批准不涵盖提醒或重发，也不涵盖其他学校的邀请。

推荐信由推荐人按学校流程撰写并提交；本 skill 不代替推荐人写信或进入推荐人的提交链接。学校的当前申请声明和 AI 使用要求必须在涉及相关内容时读取；不能把机械录入授权扩展成代写主观经历或作申请真实性承诺。

若保存普通页面同时会付款、提交或发送通知，这个保存动作按其实际后果处理，不能只因按钮写着 Save/Continue 就直接执行。`draft_only` 中即使所有材料齐全，也止于核验草稿；提交范围的改变应交给 manager 更新后，再执行独立的具体审核。

## 保存证据和恢复

对普通字段以页面/区块为单位核验，避免每个无风险按键都打断用户。必要的核验包括下拉项是否真正选中、日期格式、成绩与量纲、字符长度、不可见截断、保存标志和错误提示。重新进入已保存页面能提供较强证据；无需为机械重复而重复检查已稳定的页面。

遇到错误，先判断是本地校验、会话失效、门户服务错误还是已发生动作但响应丢失。对只读操作和可确认未生效的普通字段可进行有限恢复；同一问题经过一次有依据的修正仍失败，就记录具体阻碍并交回，不循环提交。

恢复任务时按顺序读取本地检查点、当前门户状态和未完成审核。对外部动作以门户可验证状态为依据；本地记录显示“准备执行”或旧页面按钮已点击都不足以判定成功。不确定时保留不确定性，不把失败写成成功，也不重新触发一次可能已完成的动作。

退出前保存可安全保存的草稿并记录下一步。若当前页面上的 Save 会越过尚未批准的边界，保持页面并交回用户，说明哪些内容尚未保存。对外说明用户能理解的完成情况，无需输出密码、内部工具细节或完整个人资料。
